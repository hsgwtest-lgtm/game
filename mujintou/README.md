# 無人島プロジェクト（PWA）

Instagram 連載「フォロワーが住む無人島」の公式 PWA です。動画がない日でも島を見に行ける窓として、島のライブ表示・島民検索・年表・投票お題・島民ランキングを見せます。

- フォローした人は、島の砂浜に**漂着**して島民になります。島民はドット絵のスプライトで、時刻をもとにした決定的なシミュレーションで勝手に暮らします（同じ時刻に開けば、誰の端末でも同じ光景）。
- サーバー処理はありません。島の状態は `data/*.json` に置き、運用者がエピソード（動画1本＝島の1日）ごとに差し替えます。
- 公開先（予定）：GitHub Pages（game リポジトリの `mujintou/` フォルダ）。このフォルダの中身をそのまま置けば動きます。ビルド工程はありません。

## ローカルで動かす

```sh
cd site
python3 -m http.server 8000
# → http://localhost:8000/ をひらく
```

`file://` で直接ひらくと ES modules と JSON の読み込みが動かないので、必ず http で配信してください。

確認用の URL パラメータ（組み合わせ可）：

| パラメータ | 内容 |
| --- | --- |
| `?demo` | `data/demo/` のデモデータ（5日目の育った島）を表示 |
| `?who=<島民のID>` | その島民を選んだ状態で開く（例：`?demo&who=sample_nagisa`） |
| `?t=<エポックms か ISO日時>` | 島の時刻を指定（例：`?t=2026-11-16T12:00:00+09:00`） |
| `?freeze` | 時計を止める（スクリーンショット用。`?t=` と一緒に使う） |
| `?hour=12` | 空の明るさを指定の時刻に固定 |
| `?debug` | 地面をタップすると座標・高さ・地区を表示（拠点の座標を調べるときに便利） |
| `?nosw` | Service Worker を使わない |

## データの更新手順（エピソードごと）

動画1本＝島の1日です。動画を出すたびに、次の順で `data/` を更新します。日常のデータ更新だけなら `sw.js` を触る必要はありません（データは常にネットワーク優先で読まれます）。

1. **`state.json` の `day` を1つ進め、`updatedAt` をその日の日付にする**（例：`"2026-11-17"`）。
2. **漂着者を名簿に足す**（`islanders.json`。書き方は「島民の追加」）。`joinedDay` はその日。
3. **年表に出来事を足す**（`state.json` の `chronicle`）。採用された投票結果は `vote` に書く。

   ```json
   { "day": 2, "date": "2026-11-17", "title": "拠点が決まった", "text": "島の真ん中の平原に広場をつくることに。",
     "vote": { "question": "拠点はどこにする？", "adopted": "島の真ん中の平原", "note": "いいね最多のコメントを採用" } }
   ```

4. **投票お題を差し替える**（`currentVote`）。締切は日本時間つきで書く。投稿の URL があれば `postUrl` に（無ければ連載アカウントのページへ案内します）。

   ```json
   "currentVote": {
     "id": "vote-002", "status": "open", "question": "最初に建てるものは？", "description": "…",
     "options": [ { "key": "A", "label": "小屋", "note": "雨風をしのげる" }, { "key": "B", "label": "畑", "note": "…" } ],
     "deadline": "2026-11-19T21:00:00+09:00", "postUrl": "https://www.instagram.com/p/xxxx/", "result": null
   }
   ```

   - `status`：`open`（受付中）／`counting`（集計中）／`closed`（終了）。締切を過ぎると自動で「集計中」表示になります。
   - 結果を載せたまま見せたいときは `"result": { "key": "A", "note": "いいね最多のコメントを採用" }`。
   - 受付中のお題が無い日は `"currentVote": null`。
5. **建物ができたら足す**（`buildings`）。種類は `hut`（小屋）・`field`（畑）・`pier`（桟橋）・`watchtower`（見張り台）。座標は `?debug` で地面をタップして調べられます。`builtDay` が今日より先のものは、その日まで表示されません（先に書いておけます）。

   ```json
   { "id": "hut-1", "type": "hut", "name": "はじまりの小屋", "x": -2, "z": -7, "rot": 0, "builtDay": 3, "note": "" }
   ```

6. **拠点が決まったら `base` を書く**（次の章）。
7. **行動範囲が広がったら `districts` を書きかえる**（「行動範囲」の章）。
8. 公開前に JSON の文法を確かめる：`python3 -m json.tool data/state.json > /dev/null && python3 -m json.tool data/islanders.json > /dev/null`

`state.json` の主な項目：

| 項目 | 内容 |
| --- | --- |
| `islandName` | 島の名前（無ければ `js/config.js` の仮称「無人島プロジェクト」） |
| `day` | 何日目か |
| `updatedAt` | データを更新した日（画面の下に「データ更新：」として出る） |
| `sample` | デモ用のサンプルなら `true`（「サンプル」の注記が出る）。本番は `false` |
| `base` | 拠点（広場）。決まるまでは `null` |
| `districts` | 地区ごとの、島民の行動範囲 |
| `buildings` | 建物 |
| `chronicle` | 年表 |
| `currentVote` | 現在の投票お題 |

## 公開時の初期状態（未開拓）と第1回

`data/` には公開時の初期状態が入っています（DESIGN.md「初期状態と第1回の動線」どおり）。

- 1日目。建物なし。**拠点（広場）もまだ無い**。島民が来たら、**漂着した東の砂浜**が仮の集まり場になります。
- 島民の行動範囲は**砂浜・入り江・平原**。森と高原は自然の障壁で範囲の外。
- 島民は0人（名簿は空）。
- 現在の投票は「**拠点はどこにする？**」（A 島の真ん中の平原／B 入り江のほとり／C 漂着した砂浜）。
- 年表は1日目の1件だけ。

公開する前に、次の3つを入れてください：

- `currentVote.deadline`（締切。今は `null` なので締切は表示されません）
- `currentVote.postUrl`（第1回の投稿 URL）
- `updatedAt` と、年表1日目の `date`（公開日）

## 拠点が決まったら（`base`）

「拠点はどこにする？」の結果が出たら、`state.json` の `base` を書きます。そこに広場の地面とたき火・丸太のいすが現れ、島民はそこへ集まるようになります。地図上の地区名も、拠点のある地区は拠点の名前で出ます。

| 採用された案 | `base` に書く内容 |
| --- | --- |
| A 島の真ん中の平原 | `{ "name": "中央の広場", "x": 0, "z": 5, "decidedDay": 2 }` |
| B 入り江のほとり | `{ "name": "入り江の広場", "x": -12, "z": 47, "decidedDay": 2 }` |
| C 漂着した砂浜 | `{ "name": "砂浜の広場", "x": 75, "z": 43, "decidedDay": 2 }`（砂地のままで、たき火が置かれます） |

`decidedDay` は結果を発表する日（その日から表示）。`name` は自由に変えてかまいません。あわせて年表に、採用された投票結果つきの記事を足してください。

## 行動範囲（住民の投票で広がる）

地区にシステム上の鍵はありません。島民はふだん**行動範囲の中だけ**で暮らします（行き先を範囲の中から選ぶ）。森には獣がいて歩きにくく、高原は寒くて足場が悪い――という**自然の障壁**があるからです。範囲の縁（森や高原との境目）にいる島民は、たまに「森は危険そうだ…」「あの上は寒そうだ」のようなセリフを吹き出しでつぶやきます。これが後の「行ってみようか」投票への伏線になります。

範囲を広げるのは運営ではなく**住民の投票**です。年表タブの上の「島のいま」に、拠点と行動範囲が出ます。

地区の ID：

| ID | 地区 | 公開時 |
| --- | --- | --- |
| `beach` | 砂浜（東。漂流者が打ち上がる） | 範囲の中 |
| `cove` | 入り江（南） | 範囲の中 |
| `plain` | 平原（島の真ん中。拠点の候補地） | 範囲の中 |
| `forest` | 森（西） | 範囲の外（獣の気配・歩きにくい） |
| `highland` | 高原（北東） | 範囲の外（寒い・足場が悪い） |

投票で「森に入ってみよう」が採用されたら、`districts` の森をこう書きかえます：

```json
{ "id": "forest", "inRange": true, "expandedDay": 9,
  "reason": "住民の投票で、森に入ってみることに決まった",
  "vote": { "question": "森に入ってみる？", "adopted": "入ってみよう", "note": "いいね最多のコメントを採用" } }
```

- `expandedDay`：範囲が広がった日。今日より先の日を書くと、その日までは範囲の外のまま（先に書いておけます）。
- `reason` / `vote`：住民が決めた理由と、決め手になった投票。
- 拡大は**必ず年表に「住民の決定」として残ります**。年表に記事を書かなかった場合は、`districts` の記録から「行動範囲が森まで広がった」という記事が自動で年表に入ります。自分で記事を書くときは、その記事に `"expands": ["forest"]` を付けてください（自動の記事は出なくなり、記事に「行動範囲が広がった」の印が付きます）。
- 範囲の外の説明文は `"barrier": "…"` で上書きできます。セリフや呼び名は `js/config.js` の `BARRIERS` にあります。
- 集まり場（拠点、まだ無ければ漂着した砂浜）のある地区は、書き方にかかわらず常に範囲の中として扱います。

## 島民の追加（実フォロワーへの差し替え）

公開時の名簿は空です。デモ用のサンプル島民は `data/demo/` に分けてあり、本番の名簿には入っていません。

毎回の追加の流れ（DESIGN.md「島民の追加ルール」）：

1. 連携で @eiei_mus のフォロワー一覧を読む
2. 前回の名簿との差分（新しいフォロワー）を出す
3. `islanders.json` の `islanders` に追加する（下の形。漂着日＝その日。仕事・色・住む地区は自動で割り当て）
4. リポジトリのデータを更新して PWA に反映
5. 次の動画で「◯人が漂着」と報告

```json
{
  "id": "instagram_id",
  "name": "表示名",
  "joinedDay": 2,
  "since": "2026-11-17",
  "home": "beach",
  "job": "漁師",
  "color": "#3f8fd6",
  "relationships": []
}
```

| 項目 | 内容 |
| --- | --- |
| `id` | SNS の ID（重複不可。検索にも使われる） |
| `name` | 表示名（無ければ ID） |
| `joinedDay` | 漂着した日（島の◯日目）。在住日数はここから自動計算。今日より先なら、その日まで表示されない |
| `since` | 在住の起点（日付）。詳細パネルに出る |
| `home` | よく散歩する地区（`beach` / `cove` / `plain` など行動範囲の中の地区）。省略時は `beach` |
| `job` | `漁師` / `農家` / `大工` / `探検家` / `料理人`（帽子・道具・仕事場が変わる。ほかの文字でも可） |
| `color` | 服の色（`#rrggbb`） |
| `relationships` | 関係：`{ "id": "相手のID", "type": "friend", "affinity": 0〜100 }`。`type` は `friend`（仲良し）/ `crush`（片想い）/ `mutual`（両想い）/ `rival`（ライバル）/ `quarrel`（けんか中）/ `family`（家族） |
| `anonymous` | 名前を出したくない人は `true`（名札・一覧で「匿名の島民」になり、ID も出ない） |

- フォローを外した人は、基本的に名簿に残します（DESIGN.md）。
- `"sample": true` はデモ用の印です。本番の島民には付けないでください。
- 本人に自分の島民を見せたいときは `?who=<ID>` の URL を案内できます。

## デモデータ（`data/demo/`）の読み方

`data/demo/` には「何日か開拓が進んだ島」の例（以前のサンプルデータ）が入っています。本番の画面では読み込まれません。

- 見かた：URL に `?demo` を付けて開く（例：`http://localhost:8000/?demo`、公開後は `…/mujintou/?demo`）。
- 中身：5日目、島民6人（`sample: true` の仮名。一覧に「サンプル」の印）、建物3つ（はじまりの小屋・みんなの畑・入り江の桟橋）、拠点＝中央の広場（2日目に決定）、年表4件、投票「次に建てるものは？」。行動範囲は公開時と同じ（森・高原は範囲の外）。
- 使いどころ：画面や動画素材の確認、機能の動作確認、データの書き方の見本。
- 同じ光景を再現するには時刻を固定します。例：`?demo&freeze&t=1794798200300&hour=12&who=sample_koharu`（こはるが森の手前で「獣の声が聞こえた気がする」とつぶやく瞬間）。

## 画面の見え方の調整（`js/config.js`）

- `DEFAULT_ISLAND_NAME`：島の仮称（`state.json` の `islandName` が優先）
- `INSTAGRAM_HANDLE` / `INSTAGRAM_URL`：投票カードの案内先
- `SIM`：暮らしの速さ・集まる頻度・会話の頻度
- `MAX_LABELS`：同時に出す名前ラベルの上限（カメラに近い順）
- `LABEL_ZOOM`：ラベルの段階表示。引きの全体表示では地区名だけ、寄るにつれて島民名が現れ、近いほど大きな字になる
- `BARRIERS`：行動範囲の外の説明、境界スポットの呼び名、境界でつぶやくセリフ

## PWA

- `manifest.webmanifest`：名前「無人島プロジェクト」、短い名前「無人島」、`display: standalone`、テーマ色 `#2a9fd0`、背景色 `#8fd6f5`、アイコンは `icon.svg`（`any` と `maskable`）。
- `sw.js`：
  - シェル（`index.html`・CSS・JS・Three.js・アイコン）は**キャッシュ優先**。一度開けばオフラインでも開けます。
  - `data/*.json`（`data/demo/` も）は**ネットワーク優先**。島の更新はすぐ届きます。通信できないとき（4秒以上待たされたときも）は前回取れたデータで開きます。
  - **プログラムを変えたら `sw.js` の `VERSION` を上げてください。** 新しい版は裏で取り込まれ、利用者が画面を裏に回したとき（アプリを閉じた・切り替えた）に入れ替わります。島を見ている最中に勝手に読み直すことはありません。
  - JS や CSS のファイルを増やしたら、`sw.js` の `SHELL` にも足してください。
  - データ（`data/*.json`）だけの更新では `VERSION` を上げる必要はありません。
