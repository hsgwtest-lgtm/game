# NURIBOTS — ごほうびで育てるAIぬりバトル

16×16マスのアリーナで、2体のロボが床を自分の色にぬり合う陣取りバトル。
ロボは **あなたが操作するのではなく**、あなたが決めた **「ごほうび（報酬関数）」** をたよりに
**強化学習（PPO）** で自分で動き方を覚えていきます。画面はすべてドット絵、iPhone の PWA として遊べます。

`https://hsgwtest-lgtm.github.io/game/nuribots/`

## あそびかた

| モード | 中身 |
| --- | --- |
| **ごほうび設計** | 13種類の「ごほうびカード」から最大4〜6枚を選び、それぞれの値（レベル -3〜+3）を決める。＋はごほうび、−は罰 |
| **トレーニング** | ブラウザの中で PPO が動き、ロボが学習する。学習中もカードの値を変えられ、行動がだんだん変わっていく |
| **CPUリーグ** | 9人のライバル（ルールで動くCPU 6人＋強化学習AIのボス3人）に順番に挑む。勝つと新しいカード・アリーナ・デッキ枠が手に入る |
| **オンライン** | ライブ対戦（ルームコード／クイック対戦、1本勝負 or 3本勝負）と、登録されたロボに挑むゴースト対戦 |
| **アルバム** | 学習のとちゅうの脳が自動で残る。過去の自分と戦ったり、その脳にもどしたりできる |

### ルール
- 行動は 6つ: とまる／上／右／下／左／ペンキ弾
- 入ったマス・立っているマスが自分の色になる。240手（40秒）でマスが多いほうの勝ち
- ペンキ弾: 向いている方向へ最大4マスをぬり、当たった相手は8手ピヨる（その後6手は無敵）。クールタイム10手
- ペンキ爆弾: ときどき出現。拾うとまわり13マスを一気にぬる
- アリーナは6種類（ひろば・はしら・いけ・しま・めいろ・ジグザグ）。どれも点対称で、どちらのロボにも公平

### ごほうびカード（報酬関数のパーツ）
| カード | もらえるとき | 単位 |
| --- | --- | --- |
| ぬる | まっさらな床をぬった | 0.5／マス |
| うばう | 相手の色をぬりかえた | 0.5／マス |
| かつ | 試合の最後に勝ち(＋)・負け(−) | 5／試合 |
| ムダ足 | 何もぬれなかった手 | 0.1／手 |
| ぬられた | 自分の色をぬりかえられた | 0.5／マス |
| 命中 | ペンキ弾を当てた | 2／回 |
| ピヨった | 当てられた | 2／回 |
| ばくだん | ペンキ爆弾を拾った | 2／こ |
| たんけん | この試合ではじめて入るマス | 0.2／マス |
| ちかづく | 相手に1歩近づいた（はなれても罰なし＝わざとワナ） | 0.2／歩 |
| リード | 毎手、(自分のマス−相手のマス)÷床 | 0.1／手 |
| うつ | ペンキ弾をうった | 0.25／発 |
| かべ | かべにぶつかった | 0.25／回 |

報酬は「値 × レベル × できごとの回数」の合計。ロボは勝ち負けそのものは知らず、この合計を大きくしようとするだけなので、
へんなごほうびを入れると、へんな方法で稼ぎはじめます（**報酬ハッキング**）。実況コーチがそれを見つけて教えてくれます。

### 学習の過程を「見る」ための仕掛け
- **ライブ試合**: いまの脳で戦う試合。3秒ごとに最新の脳に入れかわり、動きがその場で変わっていく
  - 矢印＝方策（各行動をえらぶ確率）、`きもち`＝価値関数のマップ（各マスにいたら、この先どれだけごほうびがもらえそうか）
  - ロボの頭の上に、その手でもらったごほうびがポップする
- **グラフ**: 勝率・床の割合・1試合のごほうび・迷い（エントロピー）・価値の当たり（説明できる分散）
- **ごほうび**: カードごとの稼ぎ（どのカードでごほうびを得ているか）。ここで値を変えると学習にすぐ反映
- **せいかく**: 6軸レーダー（ぬり・うばう・攻撃・回避・爆弾・勝率）と性格のひとこと、相手ごとの勝率
- **アリーナ**: 学習中に同時に進む8試合。「観察」スピードにするとゆっくり見える
- **のう**: AIの目（7×7マス）、64＋64個のニューロンの活動、6つの行動の確率、価値の予想
- **実況コーチ**: はじめての勝利・勝ち越し・自己ベスト・報酬ハッキングの気配・ごほうびと勝敗のズレ などを実況

## オンライン対戦（Firebase）

Firebase Realtime Database の REST API とストリーミング（EventSource）を使います。SDK は使いません。
データは softevo と同じデータベースの `nuribots/v1/` の下に置きます。
**Firebase コンソール → Realtime Database → ルール** に次の1行を足してください（ほかのゲームのルールはそのまま）:

```json
{
  "rules": {
    "leaderboard": { ".read": true, ".write": true },
    "softevo8": { ".read": true, ".write": true },
    "nuribots": { ".read": true, ".write": true }
  }
}
```

別のデータベースを使う時は、URL に `?db=https://<あなたのDB>.firebasedatabase.app` を付けて一度開くと、その端末の接続先が変わります（設定画面で元にもどせます）。

### しくみ
- 試合は **決定論的**: 乱数は整数演算だけ、ニューラルネットは四則演算と ReLU だけ、行動の確率は自作の `exp`（四則演算のみ）で計算。
  → seed と2つの脳が同じなら、iPhone でも PC でも同じ試合になる（`tools/determinism.mjs` で Node とブラウザの一致を確認）
- 送るのは **脳（8bit量子化＋float32の倍率をバイナリのまま base64、約28KB）・開始時刻・スタンプ** だけ。
  両端末がそれぞれ試合を計算するので、毎フレームの通信なしに「同じ試合が同時に」見える。開始時刻はサーバー時計とのずれを測って合わせる
- **ライブ対戦**: ホストが4けたのルームを作り、ゲストが参加。クイック対戦はロビーから空いているルームをさがし、なければ自分が待つ
- **3本勝負の作戦タイム（60秒）**: 前の試合の相手の脳を相手に、その場で「対策学習」できる。相手のごほうび設計も見える。
  時間切れなら、その時点の脳が自動で提出される
- **ゴースト対戦**: `ghosts/`（名前・デッキ・戦績）と `ghostBrains/`（脳）。挑戦の結果はサーバー側の加算で記録
- だれでも書き込めるデータなので、受け取った脳・デッキ・名前は形と範囲を検証してから使う

## 技術メモ

### 全画面ドット
1. Three.js r128 で 3D を **低解像度レンダーターゲット**（iPhone 12 で 234×506 の仮想画面の一部）に描画
2. 後処理で **奥行きの段差に輪郭線 → 4×4 ベイヤーディザ → Resurrect 64 パレットに減色**
3. UI は自前のソフトウェアフレームバッファに1ピクセルずつ描画（文字は PixelMplus10 のビットマップ）
4. 3D と UI を **整数倍の最近傍拡大**で画面へ（iPhone 12 では 1仮想px = 5物理px）

### ノッチ対応
- `viewport-fit=cover` + `black-translucent` で全画面に描き、`env(safe-area-inset-*)` を仮想ピクセルに換算
- 上のバーはノッチの下から、下の操作部はホームバーの上に置く。3D の背景だけがノッチの裏まで広がる
- 3D カメラは、上下に重なる表示の分だけアリーナを内側に収める（射影行列をずらす）
- テスト用に `?safe=47,34` を付けると iPhone 12 のノッチ（上47pt・下34pt）を再現

### AI（強化学習）
- 観察 259 = まわり7×7マス×4種（自分の色・相手の色・かべ・爆弾）＋ 63（向き・弾の準備・相手の位置・射線・爆弾の位置・4×4の全体地図・残り時間・得点）
  - だいだいのロボは盤面を180度回して「自分が左上スタート」に見えるようにしている（同じ脳でどちらの側でも戦える）
- ネットワーク 259 → 64(ReLU) → 64(ReLU) → 方策6 ＋ 価値1（重み 21,255 個）
- PPO: 8アリーナ × 128手 = 1024手ごとに更新、4エポック、ミニバッチ256、γ=0.99、λ=0.95、clip 0.2、Adam、勾配クリップ 0.5
- 報酬は割引リターンのばらつきで正規化（どんな値のカードでも学習が安定する）。「好奇心」はエントロピー係数
- スパーリング相手: 勝ったCPUと次のCPU、分身（少し前の自分と、もっと昔の自分のプール）
- 学習は Web Worker で行い、画面は 60fps のまま
- ボス3人（ロボ先輩・ミラー・NURI-KING）は `tools/make_bosses.mjs` で事前に学習した脳（8bit）

## ファイル構成

```
nuribots/
  index.html  style.css  manifest.json  sw.js  icons/
  lib/three.min.js          Three.js r128（同梱：オフラインで動くように）
  js/main.js                起動・メインループ・画面の切りかえ
  js/core/                  色と画面の定数、乱数、保存（localStorage / IndexedDB）、効果音とBGM
  js/sim/                   ルール（env）、アリーナ、CPUロボ、ごほうびカード、試合（match）
  js/ml/                    ニューラルネット、PPO、トレーナー、学習ワーカー、決定論の数学、ボスの脳
  js/gfx/                   ピクセル描画、フレームバッファ、ドット文字、ドット絵、3Dワールド
  js/ui/                    入力、UI部品、グラフ、文字入力、カード編集、レイアウト
  js/net/                   Firebase（REST＋ストリーミング）、オンライン対戦
  js/game/                  セーブ、CPUリーグ、実況コーチ、試合の見せ方（spectator）
  js/screens/               各画面
  tools/                    開発用スクリプト
```

## 開発用スクリプト

```bash
python3 tools/build_font.py       # 文章を変えたらドット文字アトラスを作り直す
python3 tools/build_sw.py         # ファイルを変えたら Service Worker のキャッシュ一覧を更新
python3 tools/make_icons.py       # アイコン
node tools/check_imports.mjs      # import / export の名前チェック
node tools/lab.mjs 60 koro 0      # ブラウザなしで学習（回数, 相手, アリーナ, デッキ）
node tools/cpu_matrix.mjs         # CPUどうしの強さ表
node tools/make_bosses.mjs king 5000000 tools/boss_king.json   # ボスの脳を作る
node tools/finetune_boss.mjs tools/boss_king.json 3000000 tools/boss_king2.json tools/boss_mirror.json tools/boss_senpai.json  # ほかのボスと戦わせて仕上げ
node tools/boss_ladder.mjs tools/boss_senpai.json tools/boss_mirror.json tools/boss_king2.json  # ボスどうしの強さ
node tools/pack_bosses.mjs tools/boss_senpai.json tools/boss_mirror.json tools/boss_king2.json  # js/ml/bosses.js に書き出す
node tools/determinism.mjs        # Node とブラウザの試合が一致するか
node tools/mockdb.mjs 8124        # テスト用の Firebase もどき（?db=http://127.0.0.1:8124）
node tools/online_test.mjs out/   # 2つのブラウザでライブ対戦（3本勝負・作戦タイム・もう一回）を通しで試す
node tools/quick_test.mjs         # クイック対戦のマッチング
node tools/ui_tour.mjs out/       # 全画面のスクリーンショット
node tools/scenario_test.mjs out/ # 進んだ状態の画面とゴースト対戦
```
ブラウザを使うテスト（ui_tour / online_test / scenario_test / determinism）は Playwright（Chromium）と
`python3 -m http.server 8123` が必要です。
